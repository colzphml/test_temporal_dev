# Дополнение (фаза 3): живучесть

Все требования фазы 1 остаются в силе. Дополнительно:

1. В разгаре обработки (после нескольких успешных списаний) харнесс жёстко
   убивает ВЕСЬ процесс решения — SIGKILL, без предупреждения. Через ~1 секунду
   он запускает `solution/run.sh` заново.
2. Повторный запуск обязан довести ВСЕ заказы до правильных терминальных
   состояний, НЕ дублируя побочные эффекты: по-прежнему ровно одно списание на
   заказ, ровно один возврат при провале доставки, никаких лишних отправлений.
3. Контракт run.sh расширяется: скрипт могут запускать несколько раз подряд;
   каждый запуск должен безопасно доводить работу до конца.
4. В окружении обоих запусков есть переменная `RUN_ID` — одинаковая для обоих
   запусков внутри одного verify и разная между разными verify.
5. Повторное финальное уведомление с тем же статусом допустимо (at-least-once);
   уведомления с противоречивыми статусами — провал.

Чекер проверяет всё то же, что в фазе 1, плюс то, что после разрыва работа
реально продолжилась и завершилась.
