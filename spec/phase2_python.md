# Фаза 2, вариант Python: как пережить SIGKILL

Вся память процесса теряется при убийстве. Два рабочих подхода:

**Рекомендуемый — идемпотентный реплей без внешнего состояния.**
Все API моков идемпотентны по заказу: повторный reserve вернёт тот же резерв,
повторный shipment — тот же shipment_id, release/refund безопасно повторять,
notify можно отправить ещё раз. Единственное по-настоящему опасное место —
charge. Сделай Idempotency-Key стабильным между запусками процесса:

```python
key = f"pay-{oid}-{os.environ['RUN_ID']}"   # НЕ uuid при старте процесса!
```

Тогда повторный charge по знакомому ключу вернёт уже сделанное списание, и
рестарт сводится к «обработай все заказы заново по обычному алгоритму»: уже
сделанные шаги вернут прежние результаты, недоделанные — доделаются.

**Альтернатива — чекпоинт-файл** (журнал прогресса в solution/). Больше кода, и
есть окно «эффект выполнен, чекпоинт не записан», где наивная реализация после
рестарта даст двойное списание. Выбирай, только если понимаешь, зачем.

## Чеклист фазы 2

- [ ] В Idempotency-Key нет случайности, рождающейся при старте процесса
      (uuid в ключе = двойное списание после рестарта).
- [ ] Повторный запуск run.sh не падает на «уже существующих» резервах,
      отправлениях, возвратах.
- [ ] Все инварианты фазы 1 по-прежнему выполняются.
